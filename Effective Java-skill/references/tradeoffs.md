# Effective Java 权衡利弊表

每条原则都有适用面与代价。审查或设计时，先看"成本/何时不适用"，再决定是否套用——不判断适用性的照搬是形式主义。条目号对应 `references/item-map.md`。

## 创建与销毁

| 原则 | 收益 | 成本/代价 | 何时不适用 |
|---|---|---|---|
| 1 静态工厂 | 能命名、可缓存、返回接口/子类型、控制实例 | 静态方法不如构造器显眼；无独立文档注释位 | 简单 `new` 就清楚的类，构造器更直白 |
| 2 Builder | 多可选参数、跨字段校验、调用点自解释、目标不可变 | 每个类多一个 Builder 类；调用点多一层 | 参数 ≤3 且全必填——构造器/静态工厂足够 |
| 3 单例枚举 | 反射/反序列化免疫 | 不能懒加载（枚举初始化即实例化） | 需要延迟初始化的重资源（用 holder 或 DCL） |
| 5 依赖注入 | 可测试、可替换时钟/随机源/仓储 | 构造器参数变多；调用方要接线 | 无状态纯函数、无外部依赖的工具方法 |
| 6 避免多余对象 | GC 压力小 | 过度复用一个对象 = 可变共享陷阱 | 小对象（几十字节）省下来不值得牺牲可读性 |
| 9 try-with-resources | 确定性释放、suppressed 链完整 | 不能忘写 `close()`；接口要 `AutoCloseable` | 非 Closeable 资源（内存句柄等） |

## equals/toString/Comparable

| 原则 | 收益 | 成本/代价 | 何时不适用 |
|---|---|---|---|
| 10–11 equals/hashCode | 集合语义正确、去重/缓存成立 | 字段增减要同步两处；可变对象的放进 HashSet 会"丢" | 身份即全部的类（Thread、Connection）；逻辑相等无意义时保持默认 |
| 13 clone | （没什么收益） | final 字段无法赋值；契约脆弱 | 几乎总是——拷贝构造/拷贝工厂优先 |
| 14 Comparable | 排序、TreeMap、二分可用 | compareTo 与 equals 不一致要写进文档 | 关系不是全序的域（部分序用 Comparator 显式表达） |
| 17 不可变 | 线程安全、可自由共享、失败原子 | 每值一对象 → 分配压力；"修改"要拷贝 | 高频原地更新的场景（游戏实体、缓冲区）；用可变类+明确线程归属 |

## 类与接口

| 原则 | 收益 | 成本/代价 | 何时不适用 |
|---|---|---|---|
| 15–16 最小可见性 | 解耦、局部推理、安全 | 包内协作需 package-private 拆分 | 框架数据载体常按序列化要求放宽 |
| 18–19 组合优于继承 | 不因超类演进而破裂 | 包装类样板代码；转发方法成堆 | 超类就是为扩展设计且自用点已文档化（模板方法模式） |
| 20 接口优于抽象类 | 已有类直接实现、mixin | 接口演进只能加 default 方法 | 需要共享实现代码的骨架（skeletal implementation 仍可接口+抽象类配合） |
| 23 层次优于 tag | 多态分发、无遗漏 switch | 类数量增长 | 两三种稳定形态且数据同构——一个类+"类型安全枚举模式"也行（JDK17：sealed 后此权衡向密封层次倾斜） |

## 泛型与集合

| 原则 | 收益 | 成本/代价 | 何时不适用 |
|---|---|---|---|
| 26 不用 raw | 编译期类型安全 | 集成老代码时 warning 潮 | 类字面量 `List.class`、`instanceof List` 等泛型信息不存在的角落 |
| 31 PECS 通配符 | API 灵活性（`List<T>` 能传 `List<Sub>`） | 调用方读签名略绕；双向参数别用 | 参数既生产又消费（`Comparable`/`Comparator`）——用 `super` 但不通配 |
| 42–48 Stream | 声明式、聚合清晰、并行可得 | 栈帧深、难调试、checked 异常别扭、调试器不友好 | 有 break/continue/早退/可变状态机——for 更清晰；性能敏感的热路径先 benchmark |
| 48 并行流 | 多核加速聚合 | commonPool 共享、分裂失败的源反而更慢、并行 bug | 数据源是 `iterate`/`limit`/装箱流、汇总量大、计算 I/O 阻塞——改用 `CompletableFuture`/executor |
| 54 空集合不 null | 调用方免判空 | 空对象分配（可用共享不可变空容器消掉） | 无——这条基本没有反例 |
| 55 Optional 返回 | 强迫调用方处理缺失 | 不是零成本（分配）、不能序列化、污染栈 | 集合返回用空集合；性能极热的路径用 null + 文档，但要写清楚 |

## 异常与并发

| 原则 | 收益 | 成本/代价 | 何时不适用 |
|---|---|---|---|
| 70 checked 仅可恢复 | API 痛苦少、bug 不被吞 | 调用方必须显式处理 | 调用方能给出降级路径时才 checked；否则 runtime |
| 76 失败原子性 | 对象状态可信 | 需要临时副本/额外校验顺序 | 高性能原地更新路径——用文档写清"失败后状态未知" |
| 78 同步一切共享访问 | 无数据竞争 | 锁争用成本 | 数据不可变/线程封闭/任务结果返回式（fork-join 范式） |
| 80 executor 优于裸线程 | 线程复用、统一治理 | 需要调参/背压设计 | 一次性脚本、main 里的一次异步 |
| 81 concurrent 工具 | 免手写等待循环 | API 学习成本 | 无——这条没有反例 |

## JDK 17+ 迁移权衡

| 现代化改造 | 收益 | 成本/风险 |
|---|---|---|
| 类 → record | 一行得 equals/hashCode/toString/存取器；天然不可变透明载体 | 破坏封装不变式表达；组件为可变引用时仍需拷贝；不能继承、不能重新打开扩展；transparent 语义对外承诺 |
| tagged class → sealed + switch 模式匹配 | 编译器强制穷尽、分发收进一处 | 封闭接口对外关扩展；跨模块协议需规划 |
| `Collections.unmodifiableX` → `List.of`/`copyOf` | 构造即不可变、无包装层、null 元素直接拒绝 | `List.of` 不允许 null 元素——上游可能依赖 null 语义；每次操作拷贝 |
| 匿名类 → lambda | 短、无实例 | 需要 `this` 指向外围、需要字段状态时仍用匿名类/内部类 |
| `String +` 循环 → StringBuilder | O(n) | 一次性拼接交给编译期折叠 |
| 反射接入 → （无直接替代） | 17 的 JPMS 下 `setAccessible` 受限 | 需要 `opens`/`--add-opens`；这是架构决策不是代码技巧，别默默依赖 |
| 裸线程 → 虚拟线程（JDK21+/17 升级路径） | 百万级并发 I/O | synchronized 内阻塞会 pin 载体；17 LTS 上要显式评估升级窗口 |
