# Teach Ladder — 认知分级、讲解结构与比喻表

## 1. 分级信号（先问再教，一次问清楚）

问三句：
1. "服务器买过吗？SSH 敲过吗？" → 没有 = L0；敲过 = 至少 L1
2. "部署上线过项目吗？卡在哪？" → 上过且翻过车 = L2
3. "这次想顺便正规化吗（配置外置/HTTPS/Docker）？" → 是 = L3

| 级别 | 每步讲什么 | 每步不讲什么 |
|---|---|---|
| L0 | 是什么+为什么+怎么做+怎么验证，命令逐条带预期输出 | 原理的细节（留一句"为什么"就够） |
| L1 | 怎么做+怎么验证；概念一句话 | 是什么、为什么 |
| L2 | 排障表+红线表； ladder 作索引 | 步骤教学 |
| L3 | 契约+检查清单+红线 | 一切教学 |

降噪判据：用户说"知道了/跳过/直接给命令" → 立即降到 L1 话密。用户贴日志来 → 按 L2 排障表走。

## 2. 讲解四要素（每个 step 的固定形状）

```
是什么   一句话；新术语配比喻（见 §3）
为什么   哪个失败会咬他——没有"因为规范如此"这种虚空理由
怎么做   可直接复制的命令块；服务器/本地要标清楚在哪台执行
怎么验证 命令 + 预期输出（哪怕只是 "看到 Started XxxApplication"）；
        配置/覆盖类步骤加负面验证：故意弄坏→看到预期的坏→修回→看到如期的好
```

一个 step 缺"怎么验证" = 没交付。这是教学契约，不是文风。负面验证专治"看起来配好了"的错觉：改错密码应看到 `Access denied`，改对才恢复——见过这条双向曲线，配置链才算建立。

## 3. 比喻表（L0 专用，L1 起禁用）

| 概念 | 比喻 |
|---|---|
| SSH | 远程开你服务器的"钥匙+对讲机"：密钥是钥匙，22 端口是对讲机频道 |
| 公网 IP vs 内网 IP | 家门地址 vs 小区内部路名；快递（浏览器请求）只认家门地址 |
| 防火墙/安全组 | 小区保安（控制台，外层）+ 你家防盗门（ufw，内层）；快递到不了，先问保安 |
| jar | 把你项目+所有依赖打好的一个"压缩背包"，服务器有 JDK 就能背着跑 |
| systemd | 服务器里的"开机启动项+保姆"：崩了拉起来、重启机器也拉起 |
| JVM 堆内存 | 程序的"工作台面积"：台面占太满，别的东西（MySQL）就没地方站 |
| 环境变量配置 | 同一个背包，到不同场地换不同的"装备贴纸"——不用重打包 |
| 反向代理 | 前台接待：对外一个门牌号（80/443），里面转给干活的房间（8080） |
| 数据库只听 127.0.0.1 | 数据库只接内部内线，不接外卖电话 |
| ICP 备案 | 大陆服务器的"门牌登记"；不登记不能挂域名营业 |

## 4. 常见 misconceptions（讲到这里必须主动破）

| 用户以为 | 实际 | 在哪一步破 |
|---|---|---|
| "IDEA 里能跑，服务器当然也行" | 配置焊在 jar 里、JDK 版本、编码/时区都会翻 | step 4 打包后 |
| "绿色就绪 = 服务正常" | systemd active 只证明进程在；应用可能启动即失败 | step 6+排障 |
| "打不开就是程序挂了" | 九成是外层防火墙没放行 | step 9 |
| "密码登录就行，密钥麻烦" | 公网 22 在被持续爆破；密钥 5 分钟 | step 2/4 |
| "改配置改服务器上的文件就行" | jar 内的配置是默认值且被焊死；改它要么重新打包，要么用环境变量覆盖 | step 8 |
| "数据库和项目一起暴露方便管理" | 3306 公开 = 数据库送全网 | step 7 |
| "1核2G 先跑起来再说" | Java 服务轻松 512MB–2GB，OOM 卡死是常态 | step 1 |
| "有时间再备份" | 第一次改表结构就是第一次数据事故 | step 7 |

## 5. RED 吸收的教学动作（来自 2026-11-01 基线）

- 开头"关键决策我替你拍板"块：型号/地域/系统/规格/端口/形态一次性说清理由，新手最怕开放式选择
- 开头三条铁律：把命中率最高的三个坑前置
- 每步"❌ 报 X：先 Y"的失败分支，不藏
- 排错表按命中率排序 + 万能三步（status / journalctl / java -version）
- 时间预算写进路线图（今晚 2–4 小时），管理预期
